# 🚀 VDS-Multiplex

**VDS-Multiplex** — это легковесная PaaS-архитектура для хостинга множества независимых приложений (SvelteKit, Node.js, API) на одном VDS. Система использует единый мастер-процесс (Router) для динамической маршрутизации запросов, что позволяет экономить до 80% оперативной памяти сервера.

## 1. Архитектура системы

*   **Gateway (Router):** Мастер-процесс Node.js, который слушает порт (напр. 3000). Он считывает `Host` запроса, находит папку приложения в `apps/` и динамически импортирует его обработчик.
*   **Изоляция данных:** Каждое приложение хранится в `apps/{name}/`. Код билда лежит в `build/`, а SQLite базы данных — в `db/`.
*   **Умный деплой:** Скрипт на Node-SSH билдит проект локально и синхронизирует с VDS, не затрагивая файлы баз данных.

## 2. Подготовка сервера (VDS)

Рекомендуемая ОС: **Ubuntu 22.04 LTS** или **24.04 LTS**.

### Шаг 2.1. Обновление и базовый софт
```bash
sudo apt update && sudo apt upgrade -y
sudo apt install nginx unzip python3-certbot-nginx -y
```

```bash
curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
source ~/.bashrc
nvm install 20
nvm alias default 20
```

### Шаг 2.3. Установка pnpm и PM2
```bash
npm install -g pnpm pm2
```

## 4. Инициализация (Setup)

Запустите интерактивный скрипт настройки. Он создаст файл `.env` и полностью сконфигурирует сервер.

```bash
npm run setup
```

**Скрипт выполнит:**
*   Создание структуры папок в `/var/www/vds-multiplex`.
*   Генерацию и активацию конфига **Nginx** (Proxy Pass).
*   Генерацию конфига **PM2** (`ecosystem.config.cjs`).
*   Установку зависимостей и запуск мастер-роутера.

## 5. DNS и SSL (Три варианта)

### 5.1. Настройка DNS (Обязательно)
В панели вашего DNS-провайдера добавьте две **A-записи**:
*   `@` — IP вашего VDS.
*   `*` — IP вашего VDS (Wildcard-запись для работы всех поддоменов).

### 5.2. Выбор стратегии SSL

#### Вариант А: Автоматический сканер (Рекомендуется)
Система сама сканирует папку `apps/` и выпускает один общий SSL-сертификат для всех найденных поддоменов.
*   **Запуск:** Просто добавьте флаг `--ssl` при деплое:
    ```bash
    npm run deploy -- --app=shop --ssl
    ```
*   **Как это работает:** Скрипт на сервере соберет список всех папок в `apps/`, добавит их в запрос к Certbot и расширит существующий сертификат.

#### Вариант Б: Wildcard SSL (через DNS API)
Идеально, если у вас Cloudflare. Сертификат выпускается один раз на `*.domain.com` и работает для всех будущих поддоменов автоматически.
*   Инструкция по настройке плагина `python3-certbot-dns-cloudflare` находится в документации Certbot.

#### Вариант В: Ручной выпуск
```bash
sudo certbot --nginx -d domain.com -d sub.domain.com
```

## 6. Создание и деплой приложения

### Шаг 6.1. Создание приложения
```bash
npm run create-app my-blog
```
Это создаст папку `apps/my-blog` с готовым шаблоном `handler.js`.

### Шаг 6.2. Деплой
Выполняйте из корня проекта:
```bash
npm run deploy -- --app=my-blog --build --ssl --reload
```
**Флаги:**
*   `--app=name` — имя папки приложения.
*   `--build` — запустить билд локально.
*   `--ssl` — обновить SSL сертификаты на сервере (включая новый поддомен).
*   `--db` — отправить локальную БД на сервер (внимание: затрет серверную).
*   `--reload` — перезапустить PM2 процесс Роутера.

## 7. Управление и обслуживание

### Локальное тестирование
Браузеры автоматически направляют `*.localhost` на локальный IP.
1. Запустите роутер локально: `npm run server:dev`
2. Откройте в браузере: `http://my-blog.localhost:3000`

### Обновление движка (Router)
Если вы изменили код в папке `server/`:
```bash
npm run deploy -- --self --reload
```

### Резервное копирование (Backup)
Скачать код и базу данных приложения с сервера на локальную машину:
```bash
npm run backup my-shop
```
Архив сохранится в папку `./backups/`.

### Просмотр логов на сервере
```bash
pm2 logs gateway
```
